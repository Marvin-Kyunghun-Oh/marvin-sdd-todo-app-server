# REQUIREMENTS — 기능 요구사항

> 상태: **확정**
> 근거: `docs/PRD.md`(확정), `docs/wireframes/Marvin's_TODO_Wireframe.pdf`
> 이 문서는 Specify 단계의 산출물이며, 이후 설계·테스트의 기준이다. 기술 사항은 다루지 않는다. (`TRD.md` 참조)

## 표기 규칙

- 요구사항 ID: `REQ-001` …
- 인수 조건 ID: `AC-001-1` … (앞 숫자는 REQ 번호)
- 근거 화면: 와이어프레임 3개 화면을 아래 이름으로 부른다.

| 화면 ID | 화면 |
|---|---|
| `01-list` | 목록 화면 |
| `02-edit` | 수정 화면 |
| `03-states` | 빈 상태·예외 상태 (A. 할 일 없음 / B. 제목 없이 추가 / C. 없는 할 일) |

- 인수 조건 중 **[예외]** 표시는 정상 흐름이 아닌 경우다. `03-states`의 상태는 모두 예외 인수 조건에 포함했다.
- 오류가 나는 모든 경우, 저장된 할 일은 하나도 바뀌지 않는다. (PRD 기능 9)
- 이 문서에서 "오늘"은 한국 시간(Asia/Seoul) 기준 날짜다.

## REQ-001 할 일 추가

제목만 입력해 새 할 일을 만든다. 설명과 마감일은 비어 있고, 완료 여부는 진행 중으로 시작한다. 제목은 앞뒤 공백을 제거한 뒤 1~100자여야 한다.

- 근거: `01-list`, `03-states`(B)

| ID | Given / When / Then |
|---|---|
| AC-001-1 | **Given** 임의의 할 일 목록이 있을 때 **When** 제목 "장보기"로 추가하면 **Then** 제목 "장보기", 설명 없음, 마감일 없음, 진행 중인 새 할 일이 만들어진다. |
| AC-001-2 | **Given** 같은 제목의 할 일이 이미 있을 때 **When** 같은 제목으로 추가하면 **Then** 별개의 새 할 일이 만들어진다. |
| AC-001-3 | **Given** 제목이 앞뒤 공백을 포함할 때 **When** "  장보기  "로 추가하면 **Then** 앞뒤 공백이 제거된 "장보기"로 저장된다. |
| AC-001-4 | **Given** 제목이 정확히 100자일 때 **When** 추가하면 **Then** 할 일이 만들어진다. |
| AC-001-5 | **[예외] `03-states`(B)** **Given** 제목이 비어 있을 때 **When** 추가하면 **Then** 할 일을 만들지 않고 제목을 입력해야 한다는 오류를 알리며, 문제가 된 항목이 제목임을 알 수 있다. |
| AC-001-6 | **[예외]** **Given** 제목이 공백만으로 되어 있을 때 **When** 추가하면 **Then** 빈 제목으로 보아 AC-001-5와 같이 거부한다. |
| AC-001-7 | **[예외]** **Given** 앞뒤 공백을 제거한 제목이 101자 이상일 때 **When** 추가하면 **Then** 할 일을 만들지 않고 길이 초과 오류를 알리며, 문제가 된 항목이 제목임을 알 수 있다. |

## REQ-002 할 일 목록 조회

저장된 할 일을 전체 / 진행 중 / 완료 중에서 골라 한 번에 모두 보여 준다. 마감일이 이른 순으로 정렬하고(기한이 지난 할 일이 위에 온다), 마감일이 없는 할 일은 맨 아래에 둔다. 마감일이 같거나 둘 다 마감일이 없으면 먼저 추가한 할 일이 위에 온다. 페이지를 나누지 않는다.

- 근거: `01-list`, `03-states`(A)

| ID | Given / When / Then |
|---|---|
| AC-002-1 | **Given** 진행 중과 완료 할 일이 섞여 있을 때 **When** "전체"로 조회하면 **Then** 모든 할 일이 나온다. |
| AC-002-2 | **Given** 진행 중과 완료 할 일이 섞여 있을 때 **When** "진행 중"으로 조회하면 **Then** 진행 중인 할 일만 나온다. |
| AC-002-3 | **Given** 진행 중과 완료 할 일이 섞여 있을 때 **When** "완료"로 조회하면 **Then** 완료한 할 일만 나온다. |
| AC-002-4 | **Given** 마감일이 서로 다른 할 일이 여럿 있을 때 **When** 조회하면 **Then** 마감일이 이른 것이 위에 온다. 기한이 지난 할 일도 같은 규칙으로 맨 위쪽에 온다. |
| AC-002-5 | **Given** 마감일이 있는 할 일과 없는 할 일이 섞여 있을 때 **When** 조회하면 **Then** 마감일이 없는 할 일은 맨 아래에 온다. |
| AC-002-6 | **Given** 마감일이 같은 할 일이 둘 있을 때 **When** 조회하면 **Then** 먼저 추가한 할 일이 위에 온다. |
| AC-002-7 | **Given** 마감일이 없는 할 일이 둘 있을 때 **When** 조회하면 **Then** 먼저 추가한 할 일이 위에 온다. |
| AC-002-8 | **Given** 할 일이 100개 있을 때 **When** 조회하면 **Then** 나누지 않고 100개가 한 번에 모두 나온다. |
| AC-002-9 | **[예외] `03-states`(A)** **Given** 할 일이 하나도 없을 때 **When** 어떤 필터로 조회해도 **Then** 빈 목록이 정상 결과로 나온다. 오류가 아니다. |
| AC-002-10 | **[예외]** **Given** 선택한 필터에 해당하는 할 일이 없을 때(예: 완료한 할 일이 없음) **When** 그 필터로 조회하면 **Then** 빈 목록이 정상 결과로 나온다. |

## REQ-003 상태별 개수 제공

전체·진행 중·완료 개수를 선택한 필터와 상관없이 알 수 있다. "N개 남음"의 N은 진행 중 개수다.

- 근거: `01-list`, `03-states`(A)

| ID | Given / When / Then |
|---|---|
| AC-003-1 | **Given** 진행 중 3개, 완료 2개가 있을 때 **When** 개수를 확인하면 **Then** 전체 5, 진행 중 3, 완료 2로 나온다. |
| AC-003-2 | **Given** 진행 중 3개, 완료 2개가 있을 때 **When** "완료" 필터로 조회해도 **Then** 개수는 필터와 상관없이 전체 5, 진행 중 3, 완료 2다. |
| AC-003-3 | **Given** 진행 중 3개가 있을 때 **When** "N개 남음"을 확인하면 **Then** N은 3이다. |
| AC-003-4 | **Given** 개수를 확인한 뒤 **When** 할 일을 추가·완료 전환·삭제하면 **Then** 다시 확인한 개수는 실제 데이터와 일치한다. |
| AC-003-5 | **[예외] `03-states`(A)** **Given** 할 일이 하나도 없을 때 **When** 개수를 확인하면 **Then** 전체 0, 진행 중 0, 완료 0이 정상 결과로 나온다. 오류가 아니다. |

## REQ-004 할 일 상세 조회

할 일 한 건의 제목, 설명, 마감일, 완료 여부를 본다.

- 근거: `02-edit`, `03-states`(C)

| ID | Given / When / Then |
|---|---|
| AC-004-1 | **Given** 제목·설명·마감일이 모두 있는 할 일이 있을 때 **When** 그 할 일을 열면 **Then** 제목, 설명, 마감일, 완료 여부가 나온다. |
| AC-004-2 | **Given** 설명과 마감일이 없는 할 일이 있을 때 **When** 그 할 일을 열면 **Then** 설명과 마감일이 비어 있는 상태로 나온다. |
| AC-004-3 | **[예외] `03-states`(C)** **Given** 없는 할 일일 때 **When** 열면 **Then** 할 일을 찾을 수 없다고 알린다. |
| AC-004-4 | **[예외] `03-states`(C)** **Given** 이미 삭제된 할 일일 때 **When** 열면 **Then** 할 일을 찾을 수 없다고 알린다. |

## REQ-005 할 일 수정

제목, 설명, 마감일, 완료 여부를 한 번에 바꾼다. 설명과 마감일은 비울 수 있다. 제목 규칙은 REQ-001과 같고, 설명은 최대 1000자다.

- 근거: `02-edit`, `03-states`(C)

| ID | Given / When / Then |
|---|---|
| AC-005-1 | **Given** 기존 할 일이 있을 때 **When** 제목, 설명, 마감일, 완료 여부를 모두 바꿔 저장하면 **Then** 네 항목이 한 번에 바뀐다. |
| AC-005-2 | **Given** 설명이 있는 할 일이 있을 때 **When** 설명을 비우고 저장하면 **Then** 설명 없음으로 저장된다. |
| AC-005-3 | **Given** 마감일이 있는 할 일이 있을 때 **When** 마감일을 비우고 저장하면 **Then** 마감일 없음으로 저장된다. |
| AC-005-4 | **Given** 진행 중인 할 일이 있을 때 **When** "완료로 표시"를 켜고 저장하면 **Then** 완료 상태가 된다. 마감일은 그대로 남는다. |
| AC-005-5 | **Given** 제목이 앞뒤 공백을 포함할 때 **When** 저장하면 **Then** 앞뒤 공백이 제거된 제목으로 저장된다. |
| AC-005-6 | **Given** 제목이 정확히 100자, 설명이 정확히 1000자일 때 **When** 저장하면 **Then** 저장된다. |
| AC-005-7 | **[예외]** **Given** 제목을 비우거나 공백만 입력했을 때 **When** 저장하면 **Then** 제목 오류를 알리고, 문제가 된 항목이 제목임을 알 수 있으며, 할 일은 바뀌지 않는다. |
| AC-005-8 | **[예외]** **Given** 앞뒤 공백을 제거한 제목이 101자 이상일 때 **When** 저장하면 **Then** 길이 초과 오류를 알리고, 문제가 된 항목이 제목임을 알 수 있으며, 할 일은 바뀌지 않는다. |
| AC-005-9 | **[예외]** **Given** 앞뒤 공백을 제거한 설명이 1001자 이상일 때 **When** 저장하면 **Then** 길이 초과 오류를 알리고, 문제가 된 항목이 설명임을 알 수 있으며, 할 일은 바뀌지 않는다. |
| AC-005-10 | **[예외] `03-states`(C)** **Given** 없거나 이미 삭제된 할 일일 때 **When** 수정해 저장하면 **Then** 할 일을 찾을 수 없다고 알린다. |
| AC-005-11 | **Given** 진행 중인 할 일이 있을 때 **When** 마감일을 어제 날짜로 바꿔 저장하면 **Then** 저장되고, 그 할 일은 기한 지남이 된다. 과거 마감일도 허용한다. |
| AC-005-12 | **Given** 설명이 있는 할 일이 있을 때 **When** 설명을 공백만 입력해 저장하면 **Then** 설명을 비운 것으로 보아 설명 없음으로 저장된다. (오류가 아니다) |
| AC-005-13 | **Given** 설명이 앞뒤 공백을 포함할 때 **When** " 메모 "로 저장하면 **Then** 앞뒤 공백이 제거된 "메모"로 저장된다. 설명 길이 제한(최대 1000자)은 공백 제거 후 글자 수로 센다. |

## REQ-006 완료 ↔ 진행 중 전환

할 일의 완료 여부를 진행 중에서 완료로, 완료에서 진행 중으로 바꾼다.

- 근거: `01-list`, `03-states`(C)

| ID | Given / When / Then |
|---|---|
| AC-006-1 | **Given** 진행 중인 할 일이 있을 때 **When** 전환하면 **Then** 완료가 된다. |
| AC-006-2 | **Given** 완료한 할 일이 있을 때 **When** 전환하면 **Then** 진행 중이 된다. |
| AC-006-3 | **Given** 마감일이 있는 할 일을 전환할 때 **When** 전환하면 **Then** 제목, 설명, 마감일은 바뀌지 않는다. |
| AC-006-4 | **[예외] `03-states`(C)** **Given** 없거나 이미 삭제된 할 일일 때 **When** 전환하면 **Then** 할 일을 찾을 수 없다고 알린다. |

## REQ-007 할 일 삭제

할 일을 삭제한다. 삭제한 할 일은 복구할 수 없다.

- 근거: `01-list`, `02-edit`, `03-states`(C)

| ID | Given / When / Then |
|---|---|
| AC-007-1 | **Given** 할 일이 있을 때 **When** 삭제하면 **Then** 그 할 일은 목록과 개수에서 사라진다. |
| AC-007-2 | **Given** 할 일이 여럿 있을 때 **When** 하나를 삭제하면 **Then** 나머지 할 일은 바뀌지 않는다. |
| AC-007-3 | **[예외] `03-states`(C)** **Given** 없는 할 일일 때 **When** 삭제하면 **Then** 할 일을 찾을 수 없다고 알린다. |
| AC-007-4 | **[예외] `03-states`(C)** **Given** 이미 삭제한 할 일일 때 **When** 다시 삭제하면 **Then** 할 일을 찾을 수 없다고 알린다. |

## REQ-008 기한 지남 판단

마감일이 오늘보다 이전이고 완료하지 않은 할 일을 "기한 지남"으로 알 수 있다. 마감 당일은 지난 것이 아니고, 완료한 할 일은 해당하지 않는다.

- 근거: `01-list`

| ID | Given / When / Then |
|---|---|
| AC-008-1 | **Given** 마감일이 어제이고 진행 중인 할 일이 있을 때 **When** 조회하면 **Then** 기한 지남으로 알 수 있다. |
| AC-008-2 | **Given** 마감일이 오늘이고 진행 중인 할 일이 있을 때 **When** 조회하면 **Then** 기한 지남이 아니다. |
| AC-008-3 | **Given** 마감일이 내일이고 진행 중인 할 일이 있을 때 **When** 조회하면 **Then** 기한 지남이 아니다. |
| AC-008-4 | **Given** 마감일이 어제이고 완료한 할 일이 있을 때 **When** 조회하면 **Then** 기한 지남이 아니다. |
| AC-008-5 | **Given** 마감일이 없는 진행 중 할 일이 있을 때 **When** 조회하면 **Then** 기한 지남이 아니다. |
| AC-008-6 | **Given** 마감일이 어제인 진행 중 할 일을 완료로 전환했다가 다시 진행 중으로 되돌렸을 때 **When** 조회하면 **Then** 다시 기한 지남으로 알 수 있다. |
| AC-008-7 | **Given** 한국 시간으로 11/10 00:30(UTC로는 11/09)이고, 마감일이 11/09인 진행 중 할 일이 있을 때 **When** 조회하면 **Then** 기한 지남이다. (한국 시간 기준 오늘은 11/10이다.) |
