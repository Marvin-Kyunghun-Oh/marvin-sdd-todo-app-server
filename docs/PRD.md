# PRD — Product Requirements Document

> 상태: **초안** (사람의 검토·승인 전)
> 근거: `docs/wireframes/Marvin's TODO Wireframe.pdf` (목록 화면, 수정 화면, 빈 상태·예외 상태)
> 이 문서는 REQUIREMENTS.md의 근거 문서다. 기술 사항은 다루지 않는다. (`TRD.md` 참조)

## 1. 목적

Marvin's Todo 클라이언트 앱이 할 일을 만들고, 보고, 고치고, 지우고, 끝낸 것으로 표시할 수 있도록 데이터를 보관하고 제공하는 서버를 만든다.

## 2. 대상 사용자

- 자신의 할 일을 관리하는 개인 한 명.
- 로그인, 계정, 사용자 구분은 없다. 서버에 있는 할 일은 모두 같은 한 사람의 것이다.

## 3. 할 일의 구성

| 항목 | 설명 | 필수 | 제한 |
|---|---|---|---|
| 제목 | 할 일의 이름 | 필수 | 앞뒤 공백 제거 후 1~100자. 공백만 입력하면 빈 제목으로 본다 |
| 설명 | 부가 설명 | 선택 | 최대 1000자 |
| 마감일 | 날짜 (시각 없음) | 선택 | 없을 수 있다 |
| 완료 여부 | 완료 / 진행 중 | — | 새 할 일은 진행 중으로 시작한다 |

- 같은 제목의 할 일이 여러 개 있을 수 있다.

## 4. 서버가 제공해야 할 기능

### 4.1 목록 화면 기준

| 화면 요소 | 서버가 해야 할 일 |
|---|---|
| 할 일 목록 | 저장된 할 일을 모두 한 번에 돌려준다. 페이지를 나누지 않는다 |
| 정렬 | 마감일이 가까운 것이 위. 마감일이 없는 할 일은 맨 아래 |
| 새 할 일 추가 | 제목만 받아 새 할 일을 만든다. 마감일·설명은 비어 있고 진행 중 상태로 시작한다 |
| 필터 (전체 / 진행 중 / 완료) | 전체, 진행 중만, 완료만 골라 돌려줄 수 있다 |
| 필터별 개수 (전체 4 · 진행 중 3 · 완료 1) | 현재 선택한 필터와 상관없이 세 가지 개수를 알 수 있어야 한다 |
| "3개 남음" | 진행 중인 할 일의 개수 |
| 체크박스 | 할 일을 완료 ↔ 진행 중으로 바꾼다 |
| 삭제 버튼 | 할 일을 삭제한다 |
| "기한 지남" 표시 | 마감일이 오늘보다 이전이고 완료하지 않은 할 일을 알 수 있어야 한다. 마감 당일은 지난 것이 아니다. 완료한 할 일은 표시하지 않는다 |

### 4.2 수정 화면 기준

| 화면 요소 | 서버가 해야 할 일 |
|---|---|
| 화면 진입 | 할 일 하나의 제목, 설명, 마감일, 완료 여부를 돌려준다 |
| 저장 | 제목, 설명, 마감일, 완료 여부를 한 번에 바꾼다. 설명과 마감일은 비울 수 있다 |
| 삭제 | 할 일을 삭제한다 |
| 취소 / 목록으로 | 서버가 할 일 없음. 저장하지 않으면 변경도 없다 |

### 4.3 빈 상태·예외 상태 기준

| 상황 | 서버가 해야 할 일 |
|---|---|
| A. 할 일이 하나도 없음 | 빈 목록과 개수 0·0·0을 정상으로 돌려준다. 오류가 아니다 |
| B. 제목 없이 추가 | 할 일을 만들지 않고, "제목을 입력해 주세요"에 해당하는 오류를 알린다. 저장된 데이터는 바뀌지 않는다 |
| C. 없는 할 일을 열었음 | 없거나 이미 삭제된 할 일이라는 것을 알린다 |

- 수정·완료 표시·삭제 시에도 대상이 없으면 C와 같이 알린다.
- 저장 시 제목이 비었거나 길이 제한을 넘으면 B와 같이 오류를 알리고 변경하지 않는다.

## 5. 범위

### 5.1 범위 안

- 할 일 추가 (제목만)
- 할 일 목록 조회 (전체 / 진행 중 / 완료), 마감일 순 정렬
- 필터별 개수 제공
- 할 일 상세 조회
- 할 일 수정 (제목, 설명, 마감일, 완료 여부)
- 완료 ↔ 진행 중 전환
- 할 일 삭제
- 입력 오류, 대상 없음 오류 알림

### 5.2 범위 밖

- 로그인, 계정, 여러 사용자
- 검색, 태그, 카테고리, 우선순위
- 반복 일정, 알림
- 페이지 나누기
- 삭제한 할 일 복구 (휴지통)
- 정렬 방식 선택
- 서버 재시작 후 데이터 보존 (TRD: 인메모리 DB)

## 6. 열린 항목 (사람이 확인)

1. **"기한 지남" 판단 날짜**: 서버 날짜 기준으로 한다고 가정했다. 클라이언트 지역 날짜와 다를 수 있다.
2. **같은 마감일 안의 순서**: 정하지 않았다. 추가한 순서(오래된 것이 위)로 하자고 제안한다.
3. **완료 처리 시 마감일**: 완료해도 마감일은 그대로 둔다고 가정했다.
4. **수정 화면의 "취소"**: 서버와 무관하다고 보았다 (클라이언트가 저장하지 않고 닫음).
5. **빈 마감일 표현**: 수정 화면에서 마감일을 지워 저장하면 마감일 없음으로 본다고 가정했다.
