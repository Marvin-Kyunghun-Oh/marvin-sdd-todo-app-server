# PRD — Product Requirements Document

> 상태: **확정**
> 근거: `docs/wireframes/Marvin's_TODO_Wireframe.pdf` (목록 화면, 수정 화면, 빈 상태·예외 상태)
> 이 문서는 REQUIREMENTS.md의 근거 문서다. 기술 사항은 다루지 않는다. (`TRD.md` 참조)
> 와이어프레임의 예시 데이터, 표시 순서, "[미정]" 표기는 참고용이며, 규칙은 이 문서를 따른다.

## 1. 목적

Marvin's Todo 클라이언트 앱이 할 일을 추가하고, 보고, 고치고, 지우고, 완료로 표시할 수 있도록 할 일 데이터를 보관하고 제공하는 서버를 만든다.

## 2. 대상 사용자

- 자신의 할 일을 관리하는 개인 한 명.
- 로그인, 계정, 사용자 구분은 없다. 서버에 있는 할 일은 모두 같은 한 사람의 것이다.
- 서버를 직접 쓰는 것은 클라이언트 앱이며, 사용자는 앱 화면으로 서버의 기능을 쓴다.

## 3. 핵심 기능

### 3.1 할 일의 구성

| 항목 | 설명 | 필수 | 제한 |
|---|---|---|---|
| 제목 | 할 일의 이름 | 필수 | 앞뒤 공백 제거 후 1~100자. 공백만 입력하면 빈 제목으로 본다 |
| 설명 | 부가 설명 | 선택 | 앞뒤 공백 제거 후 최대 1000자. 공백만 입력하면 설명 없음으로 본다 |
| 마감일 | 날짜 (시각 없음) | 선택 | 없을 수 있다. 오늘 이전 날짜도 정할 수 있다 |
| 완료 여부 | 완료 / 진행 중 | — | 새 할 일은 진행 중으로 시작한다 |

- 같은 제목의 할 일이 여러 개 있을 수 있다.

### 3.2 기능 목록

1. 할 일 추가 — 제목만 받아 만든다. 설명·마감일은 비어 있고 진행 중으로 시작한다.
2. 할 일 목록 조회 — 전체 / 진행 중 / 완료로 골라 볼 수 있다. 마감일이 이른 순으로 정렬하며(기한이 지난 할 일이 위에 온다), 마감일이 없는 할 일은 맨 아래에 둔다. 마감일이 같거나 둘 다 마감일이 없으면 먼저 추가한 할 일이 위에 온다. 페이지를 나누지 않고 한 번에 보여 준다.
3. 상태별 개수 제공 — 전체·진행 중·완료 개수를 선택한 필터와 상관없이 알 수 있다. "N개 남음"은 진행 중 개수다.
4. 할 일 상세 조회 — 한 건의 제목, 설명, 마감일, 완료 여부를 본다.
5. 할 일 수정 — 제목, 설명, 마감일, 완료 여부를 한 번에 바꾼다. 설명과 마감일은 비울 수 있다.
6. 완료 ↔ 진행 중 전환
7. 할 일 삭제
8. 기한 지남 판단 — 마감일이 오늘보다 이전이고 완료하지 않은 할 일을 알 수 있다. 여기서 오늘은 한국 시간(Asia/Seoul) 기준 날짜다. 마감 당일은 지난 것이 아니고, 완료한 할 일은 해당하지 않는다.
9. 오류 알림 — 제목이 비었거나, 제목·설명이 길이 제한을 넘은 경우, 대상 할 일이 없는 경우를 구분해 알린다. 입력 오류는 문제가 된 항목을 알 수 있다. 오류가 나면 저장된 데이터는 바뀌지 않는다.

## 4. 화면별 기능

### 4.1 목록 화면

| 화면 요소 | 서버가 해야 할 일 |
|---|---|
| 할 일 목록 | 저장된 할 일을 마감일 순으로 모두 돌려준다 (기능 2) |
| 필터 (전체 / 진행 중 / 완료)와 각 개수 | 필터에 맞는 할 일과 세 가지 개수를 돌려준다 (기능 2, 3) |
| "N개 남음" | 진행 중인 할 일의 개수를 돌려준다 (기능 3) |
| 새 할 일 입력과 "추가" | 제목만 받아 새 할 일을 만든다 (기능 1) |
| 체크박스 | 완료 ↔ 진행 중으로 바꾼다 (기능 6) |
| 마감 표시와 "기한 지남" | 마감일과 기한 지남 여부를 알 수 있게 한다 (기능 8) |
| "수정" 버튼 | 수정 화면으로 이동하는 것은 클라이언트의 일이다. 수정 화면에서 필요한 상세 조회가 이어진다 |
| 삭제(휴지통) 버튼 | 할 일을 삭제한다 (기능 7) |

### 4.2 수정 화면

| 화면 요소 | 서버가 해야 할 일 |
|---|---|
| 화면 진입 | 해당 할 일의 제목, 설명, 마감일, 완료 여부를 돌려준다 (기능 4) |
| 제목 (필수, 최대 100자) | 빈 제목과 길이 초과를 거부한다 (기능 9) |
| 설명 (선택, 최대 1000자) | 비워도 저장된다. 길이 초과를 거부한다 |
| 마감일 | 날짜를 저장한다. 비우고 저장하면 마감일 없음이 된다 |
| "완료로 표시" 체크 | 완료 여부를 저장한다 |
| "저장" | 위 네 항목을 한 번에 바꾼다 (기능 5) |
| "삭제" | 할 일을 삭제한다 (기능 7) |
| "취소", "목록으로" | 서버가 할 일 없음. 저장하지 않으면 변경도 없다 |

### 4.3 빈 상태·예외 상태

| 상황 | 서버가 해야 할 일 |
|---|---|
| A. 할 일이 하나도 없음 (전체 0 · 진행 중 0 · 완료 0) | 빈 목록과 개수 0·0·0을 정상으로 돌려준다. 오류가 아니다 |
| B. 제목 없이 추가 ("제목을 입력해 주세요") | 할 일을 만들지 않고 제목 오류를 알린다. 클라이언트가 입력 내용을 그대로 남기므로 서버는 데이터를 바꾸지 않는다 |
| C. 없는 할 일을 열었음 ("할 일을 찾을 수 없어요") | 없거나 이미 삭제된 할 일임을 알린다. 수정·완료 전환·삭제 때 대상이 없는 경우도 같다 |

## 5. 범위 밖

- 로그인, 계정, 여러 사용자
- 검색, 태그, 카테고리, 우선순위
- 반복 일정, 알림
- 페이지 나누기
- 삭제한 할 일 복구 (휴지통)
- 정렬 방식 선택
- 목록 화면에서 마감일·설명을 입력하며 추가하기 (추가는 제목만)
- 서버를 다시 시작한 뒤 데이터 보존 (TRD: 인메모리 DB)

## 6. 성공 기준

1. 와이어프레임 3개 화면(목록, 수정, 빈·예외 상태)의 모든 동작을 서버 기능만으로 구현할 수 있다. 화면을 위해 서버가 더 해 줘야 할 것이 남지 않는다.
2. 할 일 추가 → 목록 확인 → 수정 → 완료 전환 → 삭제의 전체 흐름이 끊김 없이 동작한다.
3. 빈 제목, 길이 초과, 없는 할 일 요청에 대해 정해진 방식으로 오류를 알리고 데이터를 바꾸지 않는다.
4. 필터별 개수와 "N개 남음"이 항상 실제 데이터와 일치한다.
5. "기한 지남"이 규칙(마감일이 오늘[한국 시간 기준] 이전, 미완료)대로만 판단된다.
6. 모든 기능 요구사항(REQ)이 테스트 케이스(TC)와 연결되고, 그 테스트가 모두 통과한다.
